RUBus
RUBus.live

RUBus is a web app tracking the Rutgers University bus system.

RUBus is the leading alternative to the official Passio app and has tens of thousands of unique monthly users geo-located across the Rutgers campuses; there were 80,000+ unique users in the fall 2025 semester. In September 2025, the first month of public release, it responded to over 7 million SSL requests, delivered 38 million socket messages to all clients, and served over 100 GB of bandwidth. This was reached solely by word of mouth with minimal advertising; I expect usage to grow significantly in the future.

Passio is the bus service provider Rutgers switched to in 2023. RUBus attempts to solve many of the issues students complain plague the Passio GO! apps and website; such as having a laggy, difficult-to-use UI with inaccurate bus ETAs and routes. RUBus relies on basic bus data from Passio (positioning, capacity), but calculates all other data (ETAs, time stopped, etc.) itself. This has made RUBus by far the most accurate bus app available to Rutgers students as the other unofficial apps also rely on Passio's poorly calculated ETAs.

RUBus features real-time bus locations and ETAs, the latter proprietarily calculated on server so accurately that these can even be shown down to the second. Time stopped and past breaks are shown, giving insight into potential breaks. All data is updated live. UI elements have deep customization, even with the option to use the bus marker styles from the past bus apps Rutgers used over the years. Individual routes can easily be selected.

A chatbot for answering complex questions is also available. It's capable of answering questions about what buses stop at what stops, what routes connect buildings, bus arrivals, when a user should leave to reach a destination, service times of routes, delays, service changes, network busyness, and more. This natural language capability is especially useful for new students not yet familiar with buses or buildings. Kimi K2 and the gpt-oss family of models are currently powering the assistant.

RUBus includes an advanced navigation system that provides routing between hundreds of Rutgers campus buildings. The system utilizes matrix distance calculations to display all available bus route options between selected origin and destination points and considers both live and historical bus ETAs and wait times at stops.

Python backends track and calculate bus and stop ETAs, transmitting via WebSocket. The frontend uses a Leaflet map and is served statically while a FastAPI app sends data to the client, offloading demanding tasks to the server. I chose to make a PWA to not take up storage on phones, enable seemless updates, and unify all operating systems onto a single codebase. I believe not requiring installs is a significant reason the popularity of RUBus exploded.

This project furthered my experience with Python, web frameworks, and especially front-end JS web development. This was my first ever PWA, my first time hosting on Cloudflare Pages, and my first time launching an LLM tool-calling server. I first began on the RUBus concept in September of 2023 and have continued development in my off time for the past two years.

RUBus is not affiliated with Rutgers University or Passio Technologies.

The RUBus client is open-source.
StockScope
StockScope.net

StockScope is a real-time press release aggregator for listed companies publishing on prominent newswires.

StockScope gathers releases from public newswire APIs, filters and categorizes them, and displays them in a central feed with the goal of providing investors with a trading advantage without needing to constantly refresh multiple newsrooms. LLMs additionally provide summaries and rationale.

A Sanic backend displays data from a MongoDB database. This project expanded my experience with MongoDB (pymongo), front-end web dev (HTML/JS/CSS), scheduling, and asyncio. This was my first time using Sanic and websockets and my first time using webhooks, Google Analytics, sessions, and an async framework in production.

BrickPrices
brickprices.net

BrickPrices aggreates Lego set deals from US retailers. Sets are filtered to show only below-retail-price and in-stock deals available for purchase online. Past deals and durations are also shown.

Deals can be sorted and filtered by various criteria. This lightweight web app excludes the clutter present on these stores' individual sites in a concise, neat, and efficient manner.

The site also offers real-time push notifications as deals go live, featuring an image preview of the set and direct link to the product page in the notification.

A Flask backend is used with a MongoDB database while a scheduling container periodically updates it. Push notifications are powered by Firebase Cloud Messaging. This weekend project advanced my experience with Flask, MongoDB, and front-end web development. This was my first time using FCM and service workers.

MCServers.me
MCServers.me

MCServers.me is a Minecraft server listing platform with public server discovery, ownership verification, voting, and moderation.

Players can browse, search, and filter server listings, verify ownership of their servers, and vote on a cooldown; votes are persisted in a durable queue with exponential backoff and dead-lettering before being forwarded to Minecraft servers via Votifier.

Live server status is maintained by a polling engine that pings every listed server for online status, player counts, and version, applying a strike-based fault-tolerance model so transient outages are distinguished from genuinely offline servers. Historical telemetry is recorded continuously: each per-server status flip is appended to an immutable event log from which uptime percentages are derived, and periodic platform-wide snapshots of online/offline server counts and aggregate player populations are stored, powering a public charts page of custom SVG time-series visualizations with interactive zoom and pan.

Servers are ranked hourly by a hot-score engine combining a breakdown of roughly 40 weighted signals such as vote velocity, uptime, player counts, and recency rather than naive sorting. The platform also features favorites, flagging, moderation queues, bans, and approvals, with new servers continually being discovered and added to the platform.

The frontend is a statically-exported Next.js app styled with Tailwind and served via Cloudflare Pages while an Express + TypeScript API and a Votifier forwarding service run on Railway with MongoDB Atlas, with Prometheus metrics exposed by the backend. The monorepo is containerized with multi-stage Docker builds and a compose stack with healthchecks, and a GitHub Actions CI matrix runs an extensive Vitest suite with supertest integration tests against an in-memory MongoDB across all three services. This project significantly expanded my experience with TypeScript, Next.js, React Query, and multi-service deployments, and was my first time using Votifier, SSE, and Prometheus in production. It was also my first time operating parallel development, staging, and production environments for a single live product.

Browser Whisper
browser-whisper.pages.dev

Browser Whisper is a privacy-first, in-browser audio file-to-text web app that runs OpenAI Whisper locally using Transformers.js + Whisper ONNX checkpoints. Rather than sending audio to a cloud transcription service, it keeps recording on-device: audio is decoded in the browser, inference runs inside a Web Worker, and model artifacts are downloaded and cached from Hugging Face. Model size, inference mode (CPU via WebAssembly and GPU via WebGPU when available), and time range can be selected, while the UI streams partial results in real time.

This project furthered my experience with modern front-end JavaScript/TypeScript (Web Workers) and browser-based ML runtimes. It's intentionally lightweight from a privacy perspective: there's no server-side transcription pipeline involved: everything important happens in the browser. This was my first time using WASM/WebGPU and running inference in-browser.

Browser Whisper is open-source.
RU who
RUwho.pages.dev

RUwho is a service that allows for easier searching of the public Rutgers University people database. RUwho is unaffiliated with Rutgers.

Designed to expand upon the official search platform; it's advantageous by returning results in real-time as a query is being entered alongside returning contact info of each match without the need to open a new tab for each individual.

A Flask backend integrates with a FastAPI wrapper to fetch from the Rutgers DB. This project furthered my experience with Flask, HTML, JS, CSS (including media quieries), and CORS. This was my first time using FastAPI & SlowAPI, Waitress, Intersection Observers, New Relic (NRQL), and HTTPX (over Requests) and my first time using AJAX, localStorage, asyncio, and rate limiting in production.

joyousjohn.github.io/ruguessr

RutgersGuessr is a clone of the GeoGeussr geography-guessing game that targets the Rutgers New Brunswick campuses.

Astatine85
astn85mc.pages.dev

Astatine85 Leaderboard is a leaderboard tracker for the Astn85MC Minecraft server.

The site tracks players across 14 stat categories with daily and weekly views, sorting by rank or rank change, and surfaces a top-three podium spotlight. A live search with a keyboard shortcut and autocomplete suggestions resolves players instantly, and each player has a profile page with per-stat SVG sparklines generated from historical data and Minecraft skin avatars proxied through multiple CDNs with automatic fallback. The UI is bilingual in English and Japanese with automatic language detection via timezone and locale.

The entire site is a single self-contained page served from Cloudflare Pages in a dark, gold-accented pixel-font aesthetic. A scheduled GitHub Actions workflow snapshots the top 100 players across all categories daily, fetching per-player stats in rate-limited batches and using TLS-fingerprint browser impersonation to avoid bot detection, then commits a JSON snapshot and a per-player CSV time series with 1-day and 1-week deltas back to the repository, which the frontend parses to power the sparkline charts. A Cloudflare Worker proxies the live game API with origin gating and edge caching, serves player skins through a multi-CDN fallback chain, and tracks profile views on Workers KV using SHA-1-hashed client IPs with hourly per-visitor deduplication. A service worker applies hybrid caching with cache-first static assets and network-first JSON data, and the site is installable as a PWA. This was my first time using Cloudflare Workers and KV in production, my first scheduled data pipeline via GitHub Actions, and my first bilingual UI.

Yelvix
yelvix.pages.dev

Yelvix is a dashboard comparing the dividend yields of perpetual preferred securities issued by digital-asset treasury companies (Strategy, Strive, Bitmine, DeFi Development Corp and The Smarter Web Company).

It tracks each instrument's price, stated rate, annual dividend per share and effective yield alongside its declared payment schedule. Semi-monthly variable rates, fixed quarterly rates, weekly and daily distributions, and cumulative arrears step-ups are all modelled explicitly. Vendor-reported yields are never trusted: every figure is recomputed from raw market prices and verified issuer/SEC dividend terms.

The frontend is a React + TypeScript single-page app built with Vite, using TanStack Query for data loading, with Apache ECharts for the charts. It ships to Cloudflare Pages, and runs with no runtime backend, database, subscription or paid market-data account; open clients poll the published snapshot. Features include a sortable securities table with a yield-change (pp) column, historical charts, a dividend calendar and timeline, and per-security detail pages.

Data is collected by standalone Python adapters that read public issuer APIs and SEC filings, validate with Pydantic, then write atomic, deterministic JSON datasets guarded by a process lock. GitHub Actions run collection on exchange-aware schedules (US quotes every 15 minutes, European quotes hourly, daily close finalization, and hourly dividend checks), handling DST, holidays and early closes through XNYS, XLON and XLUX calendars. Missing data stays null rather than being fabricated, and provider closes must be corroborated by an independent verified source. Wrangler and reusable build artifacts publish data updates to Cloudflare Pages. Tests span pytest, Vitest and Playwright.

This project furthered my experience with TypeScript, React and TanStack tooling, ECharts, financial modelling, and multi-schedule GitHub Actions pipelines.
